# 内网穿透（给外地朋友用）

本机跑着的无限画布默认只有本机和局域网能访问。要让外地朋友用浏览器打开，用 cloudflared 的免费临时隧道拿一个 `https://xxx.trycloudflare.com` 地址即可：不用备案、不用公网 IP，朋友也不用装任何东西。

## 渠道在哪里维护

渠道以**管理员自己的「配置与用户偏好」**为准：在顶栏齿轮里增删渠道、填 BaseURL / API Key、拉取模型列表，点「完成」保存时，这份本地渠道会**镜像**到后台私有配置（`settings.private.channels`），前台 remote 模式用的就是镜像后的那份。

几点要知道的：

- 镜像时只有 BaseURL 和 API Key 都填了的渠道才会同步过去；一个都不完整时会跳过并提示，不会把后台渠道清空。
- 「后台 - 系统设置 - 私有配置 - 渠道」仍然可以直接编辑，但**下次在弹窗点「完成」会被覆盖**。想改渠道就改弹窗那一份。
- 「公开配置 - 系统可用模型」保持**留空**即可，留空表示「已启用渠道的模型全部开放」，读取时自动取并集（当前 256 个）。如果手动填了这个白名单，它只会缩小、不会随渠道自动变大。
- 弹窗里的渠道是按用户存的（浏览器 localStorage + `user_configs.model_config`），镜像动作只对管理员账号触发。

## 一键启动全部服务（推荐）

Windows 双击 `一键启动全部服务.bat`，macOS 双击 `一键启动全部服务.command`，一次把应用和内网穿透都拉起来：

1. 启动应用（Docker；首次运行要构建镜像，约 3~10 分钟）；
2. Windows 上额外留一个隐藏 WSL 会话保活，避免 WSL 空闲休眠把服务带下线（macOS 不需要）；
3. 轮询 `/api/health` 等后端真正就绪（最多 180 秒）——没就绪就不起隧道，否则朋友打开是 502；
4. 起 cloudflared 隧道，拿到对外地址后复制到剪贴板（Windows 用 `clip`，macOS 用 `pbcopy`），用本机做一次公网自测，然后打开浏览器。

结束时会把**本机地址**和**对外地址**一起打出来，对外地址直接发给朋友即可。应用或后端没起来时会跳过隧道并提示排查命令。

停止：Windows 用 `无限画布-停止`（停应用和保活）和 `无限画布-关闭外网访问`（只关隧道）；macOS 用 `bash ./start.sh stop` 和 `bash ./scripts/tunnel/tunnel.sh stop`。

桌面上也放了一个同名入口，它只是一句 `call` 转到项目里的这一份（和桌面 `一键启动.bat` 同样的约定：改逻辑只改项目那一份），所以两边不会各存一份实现。

> **编码和换行**：`.bat` 用 GBK 保存（配合 `chcp 936`）——cmd.exe 在 UTF-8（65001）代码页下解析含大量中文的 .bat 会错位、吞掉部分 `echo` 行，所以不要把它另存为 UTF-8。`.command` 反过来，必须是 **UTF-8 + LF**：改成 CRLF 后 shebang 会带上 `\r`，macOS 双击就跑不起来。

## 前提

- 应用已经在跑（浏览器打开 `http://localhost:3030` 能看到页面）：
  - **Windows**：双击「一键启动全部服务」或「无限画布-一键启动」，或 WSL 里 `./start.sh start`。
  - **macOS**：双击「一键启动全部服务.command」，或终端里 `./start.sh start`。
- **Windows**：WSL 会话要保持存活（启动器已经留了一个隐藏会话），WSL 休眠会让隧道断开。
  **macOS**：不用管，Docker Desktop 是常驻的。
- 装好 cloudflared；缺失时脚本会按平台打印安装命令：
  - **macOS**：`brew install cloudflared`
  - **Linux / WSL**：`~/.local/bin/cloudflared`，或从 GitHub Releases 下 `cloudflared-linux-amd64`

## 一键开启

**Windows**：双击根目录的 `开启外网访问.bat`。
**macOS**：双击 `一键启动全部服务.command`（它会连应用一起拉起来），或终端里 `bash scripts/tunnel/tunnel.sh cloudflared`。

脚本会：

1. 检查本机 3030 是否就绪（没就绪会提示先启动应用）；
2. 起 cloudflared 隧道（默认 `--protocol http2`）；
3. 拿到公网地址后复制到剪贴板，并用公共 DNS 做一次公网自测（新域名刚建好时本机 DNS 常查不到，脚本最多等 50 秒；本机确实打不开时不会自动开浏览器，只提示原因）。

拿到地址直接发给朋友，朋友用浏览器打开即可，不需要装软件、不需要 VPN。

不用了：Windows 双击 `关闭外网访问.bat`，macOS 终端里 `bash scripts/tunnel/tunnel.sh stop`；对外地址立即失效，本机访问不受影响。

## 命令行用法

```bash
bash scripts/tunnel/tunnel.sh cloudflared   # 起隧道并打印对外地址
bash scripts/tunnel/tunnel.sh url           # 只打印当前对外地址
bash scripts/tunnel/tunnel.sh status        # 隧道状态、协议、应用健康检查
bash scripts/tunnel/tunnel.sh stop          # 关闭隧道
```

- 端口默认 3030（Docker 版映射端口）；Windows 安装版前端是 3000，用 `CANVAS_PORT=3000 bash scripts/tunnel/tunnel.sh cloudflared`。
- 日志在 `logs/tunnel-cloudflared.log`，pid 与地址文件在 `.run/` 下。

## 托管账号（让朋友用你的统一 API）

「配置与用户偏好」入口只对管理员显示，普通用户和托管账号看不到——顶栏没有配置齿轮，也就改不了模型渠道和 API Key。所以让别人能用起来的方式就是给他开一个托管账号：

1. 先在「后台 - 系统设置 - 模型渠道」里配好云端渠道和可用模型（托管账号走的就是这套）。
2. 在「后台 - 用户管理」新建一个账号给他，把「托管账号」开关打开，需要的话在「允许使用的模型」里勾选他只能用哪几个（留空 = 全部可用）；保存后再编辑这个账号，在「剩余次数」里填个数字（比如 50）点「调整」。
3. 把隧道地址发给他，让他用这个账号登录。

朋友登录后：

- 顶栏只有主题切换和头像菜单，看不到也改不了模型 / API Key。
- 模型列表直接来自你配的云端渠道；如果你在「允许使用的模型」里做了限制，他就只能看到并调用那几个模型，调别的会被后端拒绝（提示「当前账号无权使用该模型」）。
- 每次生成固定扣 1 次，生成失败会自动返还。生图页的「开始生成」按钮上会显示本次要扣多少：张数越多扣得越多（选 2 张就是 2 次），宽高比选到带 `(2k)` 的档位按 1.5 倍、带 `(4k)` 的档位按 2 倍（所以 1 张 2K 是 1.5 次、1 张 4K 是 2 次）。点提交后顶部会弹一条通知告诉本次消耗了多少。
- 剩余次数可以在右上角头像的菜单里看到；用完了接口会返回「使用次数已用完，请联系管理员」，你随时在后台把数字调大即可。

没勾「托管账号」的普通用户：因为用户端已经改不了渠道了，他们只能靠后台全局开启「允许普通用户使用云端渠道」才能生成，否则会提示联系管理员。所以给别人开账号时，直接勾上「托管账号」最省事。

## 朋友那边怎么用

- 打开地址就是同一个站点：提示词库、画布、素材都能用，和你在本机看到的一样。
- 账号：用你在后台给他建的托管账号（见上一节）。用户端已经不能填 API Key 了，让他自己注册是没用的，得你先在后台开号并勾上「托管账号」。

## 安全提示

- 隧道一开，**任何拿到地址的人都能打开登录页**：能注册账号、能匿名上传文件，`/api/settings` 会暴露你在后台配置的渠道 BaseURL 和模型名（不含 API Key）。所以只把地址发给信得过的人，别发到公开群；不用了就关掉隧道。
- 建议开隧道前先去「后台 - 系统设置」把「是否允许用户注册」关掉，这样只有你在后台建的账号能登录。托管账号必须由你手动勾选，陌生人即使注册了也用不了你的统一渠道，不会产生费用。
- 管理后台密码是安装时随机生成的（见 `data/账号密码.txt` 或 `.env` 的 `ADMIN_PASSWORD`），不要改成弱口令。
- 地址随机且临时，重跑会换新地址。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 朋友打开白屏 | 隧道协议退回了 quic。**Windows/WSL** 下 WSL2 的 UDP 缓冲只有 208 KiB，吞吐被压到 ~100 KB/s，主 JS 包下不来。脚本默认已用 http2，确认 `grep -m1 'Initial protocol' logs/tunnel-cloudflared.log` 是 http2；不对就重跑脚本 |
| 本机打不开、朋友能打开 | 本机 DNS 把刚建的新域名缓存成了 NXDOMAIN。把本机 DNS 换成 `119.29.29.29` 或 `1.1.1.1`（实测 `114.114.114.114`、`223.5.5.5` 对新域名会无应答），或用手机流量验一次 |
| 打开是 502 / 530 | 应用没在跑（`http://127.0.0.1:3030/api/health` 不是 ok）或隧道抖动，重跑一次脚本。macOS 上隧道目标已改用 `127.0.0.1`：`localhost` 常解析到 `::1`，Docker Desktop 的 IPv6 转发不稳 |
| 地址突然失效 | 免费临时域名不保证可用性，重跑启动脚本拿新地址重新发 |
| 想固定地址 | 临时域名做不到，需要一台带公网 IP 的服务器 + 域名走 frp 自建中转 |

> 免费隧道走 Cloudflare 边缘，国内链路本身会抖；给朋友临时看看、协作够用，长期稳定请自建 frp。
